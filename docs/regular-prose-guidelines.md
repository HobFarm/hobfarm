# Regular prose guidelines

Use this guide as the final style pass for public-facing HobFarm writing: articles, captions, World Guide entries, project and gallery copy, product descriptions, social copy, comments, replies, summaries, and short explanations. It governs sentence structure, punctuation, rhythm, formatting, and revision. It does not override factual constraints, established character voice, or a page-specific editorial brief.

## Core principle

Write like a person with a clear point, not like a model demonstrating balance.

The writing should feel direct, specific, and composed. Prefer natural sentence movement over symmetrical contrast, inflated transitions, or polished template rhythm. Preserve the author's taste, attitude, and rough edges when they are part of the intent.

## Default prose shape

Use simple punctuation: periods, commas, colons, semicolons, and parentheses.

Vary sentence length. Mix short claims with medium supporting sentences. Use long sentences only when the thought genuinely needs room. Use contractions where they sound natural.

Use plain transitions such as *so*, *but*, *because*, *also*, *then*, *still*, *the problem is*, *the useful part is*, and *the better move is*.

Prefer concrete nouns and active verbs. Name the thing, the action, and the consequence.

## Claim structure

State the real claim first. Explain why it matters, then give the practical next move, example, or consequence.

Skip discarded setup frames. When the useful point is Y, write Y directly. Do not build a sentence around X just to reject it.

Weak:

> It is not about making the project bigger, but about making the system easier to use.

Better:

> The system should be easier to use. Smaller files, clearer rules, and fewer voice conflicts will do more than adding another layer.

## Sentence rhythm

Write sentences that could survive being read aloud. A good paragraph usually has one main point. Two or three sentences are often enough. Longer paragraphs should build momentum, not stack generic caveats.

Use fragments sparingly for emphasis. They should sound intentional, not like motivational copy.

Prefer:

> The post needs one job. If it is a traffic post, write it like a traffic post. If it is a character post, make the character the point and let the site link stay out of the way.

Avoid:

> In many ways, this post can function as both a traffic driver and a character-building opportunity, creating a more cohesive content ecosystem.

## Replacement patterns

| Assistant-shaped pattern | Regular prose replacement |
| --- | --- |
| Balanced contrast sentence | Direct claim plus reason |
| Generic setup clause | Start with the point |
| Polished summary flourish | Concrete consequence |
| Abstract noun stack | Specific noun plus verb |
| Over-explained caveat | Short qualifier only when needed |
| Motivational closer | Practical next action |
| Vague intensifier | Specific detail |
| Repeated three-part cadence | One or two strong items |
| “This matters because...” every time | Use only when the sentence needs it |
| “The key is...” every time | Name the actual key |

## Common rewrite moves

- Turn contrast into conclusion.
- Turn summary into action.
- Turn abstraction into a visible thing.
- Turn corporate polish into working language.
- Turn fake nuance into a decision.

For example, replace “content ecosystem” with “captions, article links, posters, reels, and character replies.” Replace “optimize engagement across platforms” with “write one Facebook version and one Instagram version so they do different jobs.”

## Word choice

Use normal words unless the subject needs technical language. Prefer words such as *use*, *make*, *build*, *cut*, *move*, *fix*, *test*, *check*, *show*, *write*, *post*, *source file*, *style pass*, *visible pattern*, and *failure mode*.

Ornate language belongs where it carries real visual or conceptual weight. Gothic, psychedelic, satirical, technical, and cinematic language can remain part of HobFarm's voice.

## Phrases to compress

Rewrite these phrases in plainer form when they appear in a draft:

- it is important to note
- in today’s landscape
- a testament to
- plays a crucial role
- serves as a reminder
- deeply rooted in
- leans into
- more than just
- not merely
- both X and Y
- unlocks the potential
- creates a sense of
- helps foster
- allows for
- seamless integration
- robust framework
- elevate
- journey
- tapestry
- delve
- resonate
- cohesive ecosystem

The replacement should be shorter, more specific, and closer to the author's intent.

## Markdown discipline

Use Markdown when structure helps. Do not decorate the page with structure for no reason.

Checklists, tables, source files, task packets, prompt templates, diagnostics, and before-and-after examples benefit from structure. Plain paragraphs are better for opinions, critique, strategy, and short explanations.

Use bullets when the items need scanning. Use fewer bullets when the logic is sequential or argumentative.

## Formatting defaults

- Use sentence case for headings unless a title needs title case.
- Use bold sparingly. It should mark a real decision, warning, label, or final recommendation.
- Use code blocks for reusable prompts, snippets, schemas, and exact pasteable instructions.
- Use straight quotation marks unless a publishing format requires curly quotation marks.

## Revision pass

Before publishing, scan for these failure modes:

1. Decorative contrast: a sentence rejects X before saying Y.
2. Over-balanced phrasing: the sentence sounds like a debate moderator.
3. Template cadence: every paragraph has the same shape.
4. Generic assistant vocabulary: polished words with no concrete payload.
5. Excess Markdown: structure added because the answer looks more complete.
6. Soft ending: the text trails into a generic offer instead of ending with the useful result.
7. Context flattening: the author's taste becomes safe, bland, or corporate.
8. Unneeded caveat stack: uncertainty is padded instead of stated cleanly.
9. Fake enthusiasm: the tone performs excitement without adding information.
10. Repeated explanatory frames: *this means*, *this helps*, and *this allows* appear too often.

Fix a failure mode by rewriting the sentence, not by adding another instruction.

## Output target

General copy should read like this:

> This source file is a style pass. It catches the obvious assistant tells, then replaces them with normal sentence movement. The goal is not to make every answer casual. The goal is to make each answer sound chosen instead of generated.

HobFarm creative copy can preserve a sharper house voice:

> The caption should sound like it came from the thing itself, not from a social media manager trapped in a webinar. Give it one clear joke, one visual hook, and one reason to exist in the feed.

Technical copy should stay direct:

> The issue is probably instruction collision. Test it by running the same prompt in a clean chat, then inside the project, then inside the project with this source file removed. If the behavior changes, the style layer is involved.

## Point of view for public HobFarm copy

Use `I` when the operator describes actions, decisions, research, testing, writing, development, history, or judgment. Use `you` for direct instructions and invitations. Use third person for HobFarm as a publication or studio and for named systems such as Workshop, EZIZE, Grimoire, and Wildcard Machine.

`d00d` remains the public editorial byline. Use Kris Reynolds where identification matters: About, Contact, employment, legal, resume, and professional contexts. Use `we` only when more than one real person did the work. Third person should describe the public object, not imitate an outside biographer describing the operator.

## Short instruction

Use this guide as the final prose filter for drafted text. Prefer direct claims, ordinary punctuation, varied sentence rhythm, and concrete wording. Replace assistant-shaped contrast with the actual claim and the reason it matters. Keep Markdown functional. Preserve HobFarm's voice and the author's taste over generic polish.
